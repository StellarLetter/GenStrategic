# RULES — 规则事实源（唯一权威）

本文件是**唯一规则来源**。代码、测试、文档一律以本文为准，不得自行猜测或扩展。

- 编号约定：`R<n>.<m>`；代码注释与测试名直接引用这些编号。
- 本文件**只写当前生效的最终规则**，不记录规则的由来、变更历史或讨论过程。
  变更过程与裁决记录见 [`docs/DECISIONS.md`](DECISIONS.md)。

## 1. 回合 Turn / 刻 Tick

| 编号 | 规则 |
| --- | --- |
| R1.1 | 一回合 = 1 秒，分上下两个半回合：`Turn N`（上半回合）与 `Turn N.`（下半回合）。半回合又称**刻（Tick）**。 |
| R1.2 | 游戏开局为 `Turn 0`；刻序为 `Turn 0`, `Turn 0.`, `Turn 1`, `Turn 1.`, … |
| R1.3 | 每个刻结束时触发一次结算（R7.1）。回合长 1 秒 ⇒ 每刻 0.5 秒。 |
| R1.4 | 对局由房主手动开局（`start` 帧），不设自动倒计时。 |

## 2. 地图

| 编号 | 规则 |
| --- | --- |
| R2.1 | 地图是正方形地块构成的二维矩形（`size × size`）。地块索引 `index = row * size + col`。 |
| R2.2 | 地形四类：**首都**、**平原**、**山地**、**城市**（超市）。 |
| R2.3 | 地图边长由开局玩家数 `N` 决定：`size = clamp(6 + 3N + rand(0..6), 10, 40)`，`rand` 取自地图种子。8 人局 ⇒ `size ∈ [30, 36]`。 |
| R2.4 | 地图**无任何对称结构**：地形与首都位置均独立随机。 |
| R2.5 | **首都间距**：任意两座首都的曼哈顿距离（4 相邻步数）必须 `≥ 13`，即不存在曼哈顿距离 `≤ 12` 的两座首都。首都可位于任意格子，含边缘与角落。 |
| R2.6 | 随机生成无法满足 R2.5 时，**换种子重试**，边长不变。 |
| R2.7 | 地形比例、首都周围禁山半径等生成参数集中在 `server/generals/config.py` 的 `MAPGEN_*`。 |

## 3. 兵力与控制

| 编号 | 规则 |
| --- | --- |
| R3.1 | 每个地块拥有兵力值，兵力属于该地块的控制者。 |
| R3.2 | 每名玩家初始控制自己的首都，首都初始兵力 **1**；其它地块开局无控制者（中立）。 |
| R3.3 | 城市（含首都）初始有 **40–50** 的中立兵力。 |
| R3.4 | 被非中立势力控制时，**`Turn N.` 结算**执行增长：首都与城市 **+1 兵力**；平原**每 25 回合 +1 兵力**（首次在 `Turn 25.`）。 |
| R3.5 | **视野** = 自己控制的全部地块 ⊕ 与其 8 相邻（含斜角）的地块，这些地块给出完整信息（含兵量）。 |
| R3.6 | 视野外地块不给兵量，但可识别它**是否为首都转化型城市**（R5.4）。 |
| R3.7 | 每个整回合（`Turn N.`）结算一次增长；`Turn N`（上半回合）不结算增长。 |
| R3.8 | **中立**：中立地块保有兵力，**对任何玩家敌对**，被攻打时其驻军照常参加阵地战（按 R4.3 结算，守得住则不换主），但**不发起调兵、不增长**。 |
| R3.9 | 兵力无上限。 |
| R3.10 | 观战者视野为**全图**，可见真实信息。 |

## 4. 移动与战斗

| 编号 | 规则 |
| --- | --- |
| R4.1 | 调兵请求 = `(起点, 方向, 比例)`。方向 ∈ {上,下,左,右}（**4 相邻**）。不可向山地状态的地块调兵（R4.9）。 |
| R4.2 | 实际移动兵力 = `min(ceil(起点当刻兵力 × 比例), 起点当刻兵力 − 1)`。计算结果 **`≤ 0` 的请求不处理**（按 R4.12 作废）。因此兵力为 1 的地块无法调兵。 |
| R4.3 | **阵地战**：目标地块存在非友方兵力（含移动到该地块的兵力）时，参战各方按阵营求和后互减；最大者获胜，剩余 = 最大 − 次大；**并列最大者全部归零、且不占领**。 |
| R4.4 | **攻占**：战斗后（或无战斗）目标地块到达兵力 `> 0` 即立刻被到达方占领，**占领后兵力 = 战斗结算的剩余兵力**（不与原驻军累加）。 |
| R4.5 | **遭遇战**：“根据请求发起调兵”结算完成后，**互为出发地和目标**的调兵请求（A→B 与 B→A）触发。双方在途经空间抵消，**胜方剩余兵力继续前往各自目标**（R7.2 第 3 步完成该剩余移动）。4 相邻语义下只可能双方触发。 |
| R4.6 | **己方地块**：目标势力为友方时，`目标兵力 = 原兵力 + 到达兵力`（累加，**不设上限**）。中立地块**不累加**：有驻军则先按 R4.3 互减（打不下来就还是中立），无驻军（兵力 0 的空地）时按 R4.4 由到达方直接占领，兵力 = 到达兵力。**兵力为 0 的地块不参与阵地战**（无论中立还是归他人）：到达兵力 `> 0` 即按 R4.4 由到达方占领，兵力 = 到达兵力，**任何情况下都不累加给原控制者**。 |
| R4.7 | 每名玩家每个 Tick 只处理 **1 条**调兵请求（调兵链 FIFO 弹出 1 条）。 |
| R4.8 | 同一地块在单个 Tick 内最多发出 1 次调兵（R4.7 的直接结果）。 |
| R4.9 | “山地状态的地块”= 地形为山地，或已失去视野的未知地形地块（客户端/服务端的可见地形）。服务端以**真实地形**判定（山地 = 不可通行），客户端以**可见地形**渲染。 |
| R4.10 | 攻占后，防守方立即看到该地块兵力为 `0`。 |
| R4.11 | **预调兵**：请求的起点可以是「当前归该玩家控制的地块」**或**「该玩家调兵链中任意请求的目标地块」。合法性在**发起调兵阶段**判定（R7.2），入队时不校验起点归属。调兵链允许任意形状的有向图（链、树、环均可）。 |
| R4.12 | **作废**：发起调兵阶段弹出请求时，若其起点已不归该玩家控制、或按 R4.2 算出的调兵量 `≤ 0`，则：① 该请求作废且不产生任何移动；② **本 Tick 不再为该玩家弹出下一条**；③ 链中所有（直接或间接）以其目标地块为起点的请求**一并立即作废**。作废情况立即下发给该玩家。 |

## 5. 首都与停止抵抗

| 编号 | 规则 |
| --- | --- |
| R5.1 | 每名玩家有且仅有一座**王城**（首都）。 |
| R5.2 | 攻占他人王城：占领其**全部领土**，每块地继承 `max(floor(原兵力 / 2), 1)` 兵力，控制者 = 攻占方；地形与城市/平原身份及增长规则不变，只换控制者。 |
| R5.3 | **停止抵抗**：回合结算阶段结束时，没有任何控制地块的玩家立刻出局；其首都转化为**普通城市**。 |
| R5.4 | 首都转化型城市（R5.3 产生的城市）：逻辑上等同普通城市，唯一区别是**视野外渲染为平原**（普通城市在视野外渲染为山地）。 |
| R5.5 | **投降**：玩家主动放弃并退出，进入 **40 Tick 过渡期**。过渡期内其地块仍属本人、仍按 R3.4 增长、仍会被攻打与参与战斗，仅**不能操作**（调兵链在投降瞬间清空）。过渡期结束后其**全部地块同时转为中立**，兵力完整保留；首都转化为首都转化型城市（R5.4）。 |


## 6. 操控与 UI

| 编号 | 规则 |
| --- | --- |
| R6.1 | 点击可选中一个地块。 |
| R6.2 | `W`/`S`/`A`/`D` 向相邻地块调兵，并**选中对应地块**。 |
| R6.3 | 调兵链：缓存多个调兵请求，后端按 **FIFO** 在每 Tick 结束时结算（每 Tick 弹 1 条，R4.7）。 |
| R6.4 | `Q` 取消完整调兵链；`E` 取消最新一条调兵请求。 |
| R6.5 | **点击调兵**（可开关）：点击已选中地块的相邻地块时触发一次调兵。点击调兵与键盘调兵**处理逻辑相同**。 |
| R6.6 | 调兵比例：**只取 10% 的整数倍**，即 `{10%,20%,…,100%}` 这十档。选中新地块 → 100%；再次点击当前选中地块 → 50%；`+`/`-` 按 10% 档位上下移动（到边界为止）。**比例不自动保持**：每提交一次调兵后比例立即回到 100%。真人界面与 AI 使用**完全相同的这十档**，AI 不能调出真人无法选择的比例。当前比例以 `N%` 文字叠加显示在**选中格内**（100% 时不显示）。 |
| R6.7 | 每个请求**各自记录入队时的比例**。 |
| R6.8 | 面板展示每名玩家的**兵力总和**（Army）与**控制区大小**（Land = 控制地块数，含首都与城市）。 |
| R6.9 | 视野外渲染：山地与城市 → 山地外观；其它（平原/首都）→ 平原外观；首都转化型城市 → 平原外观（R5.4）。视野内按真实地形 + 控制色 + 兵量渲染。 |
| R6.10 | **聊天栏只播报三种系统消息**：`"<name> surrendered."`、`"<name> captured <name>."`、`"<name> left."`；界面上每行前面带该玩家的颜色块（`captured` 带攻占方与被攻占方两个色块），行尾追加发生时的回合号 `N.`。玩家发言照常显示；其它系统消息（加入、开局等）不播报。 |
| R6.11 | 调兵链上限 **20 条**，超出拒绝入队。 |
| R6.12 | 排行榜首列「星数」恒为 `0`（本项目无评级系统，字段保留以对齐原站界面）。 |
| R6.13 | 观战者在 `joined` 帧的 `playerId` 为 `-1`；前端把负数一律视为「无座位 / 观战」。 |
| R6.14 | **界面布局**：地图画布铺满整个窗口，不在窗口内分栏；非地图区域（地图未覆盖的部分）用比页面底色更深的灰。回合显示、投降按钮、记分板、聊天栏是**悬浮在地图之上的面板**，可被鼠标拖动，位置按面板分别记住（刷新后保持），且始终限制在视口内。地图用鼠标拖拽平移、滚轮缩放。 |

## 7. 回合结算

| 编号 | 规则 |
| --- | --- |
| R7.1 | 结算顺序：**兵力增长 → 根据请求发起调兵 → 结算遭遇战 → 结算阵地战 → 更新占领 → 检查停止抵抗**。 |
| R7.2 | “根据请求发起调兵”（第 2 步，原子阶段）：每玩家 FIFO 弹出 1 条请求，按 R4.11 判定起点合法性、按 R4.2 计算实际兵力并从起点扣除，生成“飞行中兵力 `(来源, 方向, 兵力)`”；不合法则按 R4.12 作废。**此刻不更新任何占领**。第 3 步：互为出发/目标的请求做遭遇战抵消，胜方剩余兵力继续飞向目标（R4.5）。 |
| R7.3 | **一致原则**：结算不产生任何随机、不依赖时间；同一状态对每一方给出相同结果。所有集合遍历按 `(玩家 id, 地块 index)` 排序，禁止依赖字典插入序。 |
| R7.4 | 只剩一名拥有地块的玩家时游戏立即结束（在第 6 步之后判定）。 |
