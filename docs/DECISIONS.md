## 2026-11-24 · 第八批：策略自动挂载与「策略接管」（R6.17）

**用户原话**

> 完善 AI 接入手册，使得可以仅阅读手册就完成编写，自动挂载根目录 ai 下的所有策略，
> Web 界面可以选择本玩家由某个策略接管

**追问与澄清（用户选择）**

| 议题 | 结论 |
| --- | --- |
| 何时指定接管 | **通常在开局前指定**（开局前指定即从 `Turn 0` 第一刻起生效）；开局中切换也保留 |
| 接管对象 | **本玩家自己的座位**（真人连接仍在，可随时收回操作权） |
| 策略根目录 | 仓库根的 `ai/`（`D:\COSMOS\generals\ai`） |

**发现的问题（实现前实测）**

`Seat.bot` 从上线起只是**占位**：`Lobby.join(bot=...)` 校验了名字已注册，但
`Room` 里**没有任何代码实例化或驱动 `AIRunner`**。`test_net_ai_integration.py` 也就只能
手动 `AIRunner(...)` 去驱动座位 —— 也就是说，协议上的"机器人座位"在前端/服务端链路里是死的。

**结论与落地**

| 议题 | 结论 | 依据/影响 |
| --- | --- | --- |
| 自动挂载 | 新增 `ai/loader.py`：启动时扫描 `<repo>/ai`，把每个 `.py` 当独立模块执行其 `@register` | 用户要求"自动挂载根目录 ai 下的所有策略"；`GENERALS_AI_DIR` 可换目录 |
| 错误隔离 | 单个文件失败只进 `LoadReport.errors`，不进注册表、不阻塞启动 | 一个坏文件不该让整局游戏起不来 |
| 热重载 | `StrategyLoader.scan()` 先摘掉上一轮由文件注册的名字再重扫；`POST /api/ai/reload` 触发 | 改名/删除/改内容都即时生效，无需重启 |
| 机器人座位 | `Room` 新增 `_runners`（seat → AIRunner），`start()` 时建好、每 Tick 推进内核**之前**统一 `step()` | 修掉上面那个"bot 只是占位"的缺陷 |
| 接管机制 | 新增 `Seat.autopilot` 与 `autopilot` 帧（上行）+ `autopilot` 回执帧（下行广播） | 用户要求"选择本玩家由某个策略接管"；`bot`（无连接的机器人座）与 `autopilot`（真人座的托管）语义区分开 |
| 开局前指定 | `Room.set_autopilot()` 在 `WAITING` 阶段即可调用，`start()` 内 `_sync_runners()` 生效 | 用户明确"通常在开局前指定接管" |
| 远程策略 | Tick 循环改走 `Room.step_async()`（策略在线程池），`step_once()` 保持同步语义 | `RemoteAgent` 是同步 httpx，直接调用会卡住事件循环；同时保证**每刻只决策一次** |
| 界面 | 新增浮动面板 `web/src/ui/autopilot.ts`：下拉框列出策略、选中即发帧、可收回 | 复用 `ui/floating.ts` 的拖动与位置记忆（R6.14） |

**受影响**：

## 2026-11-24 · 修复：攻打敌方 0 兵力地块必须易手

**用户原话**

> 修复bug：进攻对方零兵力地块有概率把到达兵力叠加给对方而没有交换控制权

**原因**

`game/tick._apply_dst_result` 的「无战斗」分支原以 `dst_tile.owner is None` 作为判据：
中立空地 → 占领（R4.4），**有主地块 → 一律累加（R4.6）**。
但 `combat.resolve_battle` 只有在 `tile.army > 0` 时才把守军计入参战集合，
所以**敌方 0 兵力地块同样落入「无战斗」**，却被误当成友方地块累加 ——
到达兵力叠给了原控制者，控制权没动，`captures` 事件也不下发。

「有概率」的由来：R4.3 的平局会把守军打到 0 兵但保留控制者；
此后任何一次到达都会被白送，连敌方王城的全继承（R5.2）也一起失效。

**结论与落地**

| 议题 | 结论 | 依据 |
| --- | --- | --- |
| 敌方 0 兵力地块是否参战 | **不参战**（没有防御兵力，与中立空地同属「无战斗」） | R4.3「存在非友方兵力」才发生阵地战 |
| 控制权 | **转移给到达方**，兵力 = 到达兵力（不与原驻军累加） | R4.4 |
| 判定依据 | 由「dst 是否中立」改为「dst 的控制者是否就是唯一到达方」——R4.6 只对**友方**累加 | R4.6 |

**受影响**：`game/tick.py`（`_apply_dst_result` 改判据、去掉已无用的 `arrivals` 形参）；
`docs/RULES.md`（R4.6 补一句显式条文）；`docs/INTERFACES.md`（§1.4 注明守军 0 兵不进参战集合）；
`README.md`（内核状态补注）；测试 `server/tests/test_kernel_combat.py` 新增
`test_capture_enemy_zero_army_tile_r4_4`、`test_repeated_attack_after_tie_captures_zero_army_tile_r4_3_r4_4`、
`test_capture_zero_army_enemy_capital_inherits_r4_4_r5_2`（三条在修复前全部失败）。

## 2026-11-19 · 第五批：中立驻军正常防守、调兵作废改静默

### 变更 A：打中立城市不再累加兵力

**用户原话**

> 现在攻占中立城市兵力会叠加
>
> （追问后选定）中立兵力正常防守；敌方照旧结算。

**推导与落地**

原实现把"中立地块"归进 R4.6 的累加分支（`apply_capture` 里 `army += amount`），
于是 50 兵攻打 40 兵的**中立城市**会得到 50 或 90 兵的城市——中立驻军既没参战也没被扣除。
正确语义按 R3.8（中立对所有人敌对、可被动参战）+ R4.3（阵地战互减）：
中立驻军是一支独立势力，攻占后兵力 = `到达兵力 − 驻军`，打不过就还是中立。

| 议题 | 结论 | 依据 |
| --- | --- | --- |
| 中立驻军是否参战 | **参战**，用伪 owner `NEUTRAL_OWNER = -1` 记入参战集合 | R3.8 "对任何玩家敌对" |
| 攻占后兵力 | `到达 − 驻军`（不叠加） | R4.3 "剩余 = 最大 − 次大" |
| 打不下 | 地块仍中立，驻军减为差额 | R4.4 只在剩余 > 0 时换主 |
| 中立空地（兵力 0） | 照旧：无战斗、直接占领 | R4.6 |
| 敌方地块 | **照旧**（互减后胜方剩余兵力占城） | 用户明确"敌方照旧结算" |

**受影响**：`R3.8` / `R4.4` / `R4.6` 措辞、`game/combat.py`（`NEUTRAL_OWNER` + 守军参战）、
`game/tick.py`（中立守住的落地分支）、`game/rules.py`（`apply_capture` 只对自己地块累加）。
`NEUTRAL_OWNER` 永不写进地块，只出现在 `BattleResult.participants` / `winner` 里。

### 变更 B：调兵被作废不再弹提示

**用户原话**

> 另外调兵被取消不用专门弹出通知，静默取消调兵链及其渲染即可。

**落地**

- 线协议不变：仍下发 `chain_dropped` 事件并紧跟权威 `commands` 全量快照（R4.12 要求"作废情况立即下发"）；
- 前端删掉 `#toast` 提示条：收到作废后只按快照静默清空本地调兵链与其渲染（含选中态校正），不做任何弹窗/飘字。

**受影响**：`web/src/main.ts`（移除 toast）、`web/styles/game.css`（删 toast 样式）、README 描述。

## 2026-11-19 · 第四批：地图生成、中立语义、聊天播报、预调兵

### 变更 A：地图生成

**用户原话**

> 首都完全随机刷新但是不可出现在曼哈顿距离 12（含）内的两个首都。
>
> 地图大小由人数决定且有小幅随机变动，实际 8 人地图在 30-36。
>
> 地图无对称结构。

**推导与落地**

| 议题 | 结论 | 依据 |
| --- | --- | --- |
| 边长公式 | `size = clamp(6 + 3N + rand(0..6), 10, 40)` | "8 人 → 30..36" 是唯一锚点；线性外推 `6+3N` 在 N=8 时正好是 30，加 `0..6` 抖动得到 30..36。已实测 1..8 人 × 各尺寸区间在曼哈顿 ≥13 约束下都能放下 N 座首都。 |
| 首都约束 | 任意两首都曼哈顿距离 `≥ 13`（即不允许 `≤ 12`） | 用户原话 "距离 12（含）内不可"。 |
| 对称 | **彻底取消**，地形与首都位置独立随机 | 用户原话 "地图无对称结构"。原实现按 180° 旋转成对放首都，并带对称自检，全部删除。 |
| 生成失败 | 换种子重试，边长不变 | 用户明确（Q4）。 |
| 首都可落位置 | 任意格子，含边缘与角落 | 原实现按"离边界距离"优先选内部，该偏好删除。 |

**受影响**：`R2.3`–`R2.7`（新增）、`server/generals/game/mapgen.py`、`config.py`、`net/room.py`（房间不再允许客户端指定边长）。

> 早期实现用**切比雪夫**距离作为首都间距，与本次明确要求的**曼哈顿**距离不等价（切比雪夫更严格），已整体替换。

### 变更 B：中立语义

**用户原话**

> 中立的兵和任何人都是敌对的。
>
> 中立无调兵，但可被动参与战斗，无增长。

**结论**：中立地块保有兵力、对任何玩家敌对、被攻打时按阵地战结算，但**不发起调兵、不增长**。
这是对既有实现的明文确认（原实现已如此），升格为规则条文 `R3.8`。

### 变更 C：聊天栏播报范围

**用户原话**

> 界面优化：聊天栏仅播报停止抵抗（... captured ...）、投降（... surrendered ...）、离开（... left ...）。
> 所以可能出现某人先投降，又被攻占而停止抵抗、随后关闭页面触发离开。

**推导与落地**

| 议题 | 结论 |
| --- | --- |
| 保留的系统消息 | 只有 `"<name> surrendered."`、`"<name> captured <name>. <turn>."`、`"<name> left."` |
| 其它系统消息 | 一律不播（加入、开局提示等全部删除） |
| 玩家发言 | 照常显示 |
| 顺序 | 三条可以先后都播：投降 → 过渡期内被攻占 → 关页面离开 |
| 回合号后缀 | 用户明确（Q5）：`captured` 带回合号 |
| 无攻占者的出局 | 例如投降期满转中立导致失去全部地块，没有攻占方 → **不播** `captured` |

### 变更 D：预调兵

## 2026-11-18 · 第一批：规则原文

用户给出的初始规则（唯一事实源），要点：

1. 一秒为一个 **Turn**，分 `Turn N` 与 `Turn N.`；开局 `Turn 0`。
2. 地图是正方形**地块**二维矩形；地块类型：首都、平原、山地、超市。
3. 每地块有兵力值，属于控制者；玩家初始控制首都、1 兵力；其它地块无控制者；城市初始中立 40–50 兵力。
   非中立控制时：首都/城市每回合 +1，平原每 25 回合 +1。视野 = 自己控制区 + 8 相邻 + 视野外城市身份。
4. 每 Tick 可让己方兵力向相邻地块移动 `<出发兵力-1>`；目标存在或同时抵达非友方兵力 → 阵地战；
   战斗后兵力 > 0 → 攻占。相邻两敌对势力同时向另一地块调兵 → 先遭遇战。不可向山地调兵。
5. 每玩家仅一座王城；攻占他人王城 → 占领全部领土，每块继承 `max(floor(原兵力/2), 1)`；
   攻占回合结束时无任何地块 → 停止抵抗，首都转普通城市。
6. 点击选中；WASD 调兵并选中；可缓存多个请求（调兵链），后端按 FIFO 每 Tick 末结算；
   `Q` 取消整链，`E` 取消最新一条；可选点击调兵；面板可看其它玩家兵力与控制区大小。
7. 结算顺序：兵力增长 → 发起调兵 → 遭遇战 → 阵地战 → 更新占领 → 检查停止抵抗；
   对称一致（无随机、不同玩家结算效果相同）。
