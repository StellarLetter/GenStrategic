## 1. 三条被规则逼出来的结论

写策略之前先把规则里"真正决定胜负"的几条提炼出来。下面每条都直接决定了实现。

### 结论 1：**地块就是钱**（R3.4）

`Turn N.` 结算：首都/城市 **+1 兵/回合**，平原**每 25 回合 +1**。
所以一块平原 ≈ `1/25` 兵/回合，而**一座城市 ≈ 25 块平原**。且越早占越值钱。

⇒ 早期铺地的收益高于早期打城；地图铺满之后，**城市是唯一增量**。

### 结论 2：**比例只有十档，逼出"小堆长格 / 大堆整堆搬"的分工**（R4.2 / R6.6）

`实际调兵 = min(ceil(army × ratio), army − 1)`，比例只有 `10%…100%` 十档。

| 起点兵力 | 按 10% 送多少 | 按 100% 送多少 | 结论 |
| --- | --- | --- | --- |
| 5 | 1 | 4 | 可以"几乎免费"长一格 |
| 12 | 2 | 11 | 仍可长一格 |
| 50 | 5 | 49 | 长一格要送 5 兵 —— 不划算 |
| 80 | **8** | 79 | **绝不能用来长格** |

⇒ 于是分两条线：

* **小堆（2–12 兵）负责长新地块** —— 每格只送 1–2 兵；
* **大堆负责整堆搬运** —— 按 100% 走一格只留 1 兵（`min(ceil(army), army−1)`），
  是最省的兵力搬运方式，顺便把散兵集中成一坨。

这一条是踩过坑才写下来的：早先把所有地块一视同仁地"10% 长格"，结果 80 兵的大堆
每刻被抽掉 8 兵去占平原（8 兵换 1/25 兵/回合的产能，**要 200 回合才回本**），
兵越打越少，最后被对手 3256 兵对 1379 兵拖成平局。

### 结论 3：**只有斩首能赢，而斩首必须"一坨兵一次性砸上去"**（R5.2 / R7.4）

攻陷王城 = 继承其**全部**领土 ⇒ 立刻终局。所以：

* 兵散在地图上再多也没用 —— 守方可逐刻把邻居的兵灌进王城（R4.6 累加，不限上限）；
* 进攻方必须**在同一刻**把比守军多的兵送进王城（R4.3 取"最大 − 次大"）；
* 守军每回合 +1（R3.4），拖得越久门槛越高。

## 2. 视野限制带来的两个技巧（R3.5）

视野 = 己方地块 ∪ 其 8 邻。由此得到两个确定性的手段：

### 技巧 A：**贴脸即"精确侦察"**

一旦我方地块贴到对手王城旁边，它的驻军对我**完全可见**（R3.5 含 8 邻）。
所以"够不够打"不需要猜，直接看。

### 技巧 B：**门口削血 —— 把王城的 +1 抽掉**

贴着对手王城时，每刻送 **1 兵**进去（`ratio_for(army, 1)`）：

* 守军每刻 **−1**（R4.3 互减）；
* 王城每 2 刻才 **+1**（R3.4 只在 `Turn N.` 结算）；
* ⇒ 净流失 **0.5 兵/刻**，守军迟早被抽干；
* 对手要补就得花掉自己**每刻唯一**的调兵额度（R4.7）并从别处抽兵 —— 等于替我拖住他。

守军见底那一刻，1 兵即可拿下王城 —— 而王城一丢就是终局。这是本策略对"龟缩型对手"的解法。

## 3. 决策流程

每个 Tick 只提交 1 条指令（R4.7），按下面的顺序**每刻重新评估**：

```
0. 应急防守   敌兵贴到王城 4 邻 → 打得过就吃掉，打不过把兵拉回王城
              看得见强敌堆逼近(threat_radius 内) → 主栈回防
              ↑ 可打断任何任务：王城丢了对局就结束（R5.2）

1. assault    已贴到对手王城 → 够打就斩首；不够就门口削血；门口兵太少就续兵
2. war        已知对手王城 + 已够出征规模 → 主栈沿最短路压过去（留守家兵）
3. probe      不知对手王城 + 已占优 → 主栈朝"敌方领土重心"推进（贴脸即见地形）
4. city       贴着自己的城且一口能吃下 → 吃（+1/回合 = 25 块平原）
5. expand     小堆长新格（1 格/Tick）；长不动就把大堆整堆往前沿挪一格
6. chip       削中立城（限速，别挤掉铺地的调兵额度）
7. gather     把散兵往王城（银行）收
```

### 3.1 为什么"进攻"排在"铺地"前面

铺地只是**慢慢**增加收入，斩首是**立刻**结束比赛。
但若把铺地放前面，它每刻都有动作，会把进攻**永久饿死** —— 实测出现过
"打到 1200 刻一次都没进攻过、经济 2 倍于对手却始终平局"。
所以进攻类任务排在前面，靠**自带门槛**（要够出征规模 / 已占优）来约束；
门槛不满足时它们返回 `None`，自然轮到铺地。

### 3.2 为什么"地盘落后"要掐住进攻

地块数就是收入（结论 1）。地盘比对手少还去远征，等于拿穷国的兵换富国的兵。
所以 `war` / `probe` 都要求 `my_land >= enemy_land`（R6.8 公开数据）。
**但**一旦已经无地可铺（被山和对手围住），"回去铺地"这条退路就不存在了，
必须打出去 —— 否则只能在家被越拉越开。

### 3.3 选空地：按**可走距离** + **连通面积**

`_nearest_empty` 用 Dijkstra 算"只穿己方地块 + 空地"的真实步数（山不可过，R4.9），
再按空地所属**连通区域大小**排序。为什么不能只用曼哈顿距离：山对面那块"看着很近
其实要绕一大圈"的空地会被当成最优解，最后把自己挤进死角 —— 实测有局 48 块地就被
完全封死，剩下 190+ 块空地再也吃不到。

## 4. 关键参数（`CosmosGeneral.P`）

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `reserve_growth` | 0.35 | 王城常备驻军 ≈ 自家总兵力 × 该系数（主栈出门时的家底） |
| `reserve_cap_frac` | 0.55 | 常备驻军不超过总兵力的这个比例（别把主力钉死在家） |
| `threat_radius` | 6 | 多近算"逼近王城" |
| `sprout_max_army` | 12 | 只有兵 ≤ 该值的小块才负责长格（结论 2） |
| `sortie_turn` / `sortie_stack` | 22 / 40 | 常规出征的门槛 |
| `decisive_ratio` | 1.6 | 我方总兵力 ≥ 对手 × 该倍数 → 无视守军直接总攻（收尾信号） |
| `chip_every` / `chip_max_land` | 2 / 45 | 削城的限速 |

调参用 `tools/sweep.py`（见 §6），不要在真人对局里试。

## 5. 实测成绩

`tools/sweep.py --baseline --seeds 4 --max-ticks 1200`
（6 种对手 × 4 个种子 × **两个座位** = 48 局；地图无对称，R2.4，所以两个座位都要试）：

| 对手 | 打法 | 结果 |
| --- | --- | --- |
| `greedy`（内置） | 贪心铺地 + 打最弱邻格 | 8W / 0L / 0D |
| `zoo-snake` | 蛇形极限铺地 | 8W / 0L / 0D |
| `zoo-city` | 抢城 | 7W / 0L / 1D |
| `zoo-turtle` | 龟缩反击 | 6W / 0L / 2D |
| `zoo-rush` | 开局冲锋 | 6W / 0L / 2D |
| `zoo-raider` | 扩张 + 偷家 | 5W / 0L / 3D |
| **合计** | | **40W / 0L / 8D（得分 0.875）** |

* 胜局平均 **302 回合**（≈ 5 分钟），没有一个败局；
* 平局全部出现在 `--max-ticks 1200` 截断时，且都是我方兵力/地盘占优的收尾慢局；
* `act()` 平均 1.4 ms / 峰值 ~16 ms，远低于 R1.1 的 400 ms 预算。

> 对手 `zoo-*` 是 `tools/zoo.py` 里的自研陪练（只用于调参，在 `tools/` 里，
> 不在 `ai/` 里，所以不会出现在界面的策略下拉框里）。它们的实现只用
> `Observation`，和真人策略走同一条校验路径。

## 7. 已知短板

1. **对"完全龟缩 + 只灌王城"的对手偏慢**：本策略靠门口削血破壳，
   若对手把每刻唯一的调兵额度全用来补王城，削血收益会被抵消，只能靠兵力优势硬砸。
2. **地图被围死时不会主动破墙**：围死时（`_economy_ahead` 的放行分支）会去打，
   但没有"先撞薄墙开新地盘"的专门逻辑。
3. **不记忆对手行为**：没有"这个对手爱偷家"之类的对手模型，纯按当前局面决策。
4. **平局收尾慢**：48 局里 8 局在 1200 刻截断时仍是我方占优但未终局，
   若比赛按回合上限判分，这部分是可以再抠的分数（`decisive_ratio` 调低能加速，
   但会牺牲防守稳健度 —— 实测 1.6 是当前最优）。
